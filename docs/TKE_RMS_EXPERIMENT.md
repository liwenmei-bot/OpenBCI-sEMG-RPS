# TKE / RMS 门控对照实验

更新日期：2026-11-21。程序版本：`1.0.1-tke-rms-compare`。

对应脚本：[`../binary/08_live_rp_tke_compare_4ch.py`](../binary/08_live_rp_tke_compare_4ch.py)。

这是现有石头/布二分类模型的实时门控对照实验。目标是在固定分类器的条件下，比较旧RMS、当天RMS和当天TKE的动作触发、静息误输出、漏检和响应时间。它不保证TKE优于RMS，也不把短时工程测试当作跨日泛化结论。

## 1. 哪些步骤继续使用旧代码

原`classic`、`extended`入口继续保留。新08是独立实验入口；目前统一入口`run.py live`没有新增`--engine tke`选项。请直接运行新08，命令里不加`live`子命令。

`rps/08_today_only_svm_rps_4ch.py`是另一份三分类训练实验，与这里的二分类TKE实时脚本不同。

## 2. 三组对照

| 组别 | 活动指标与参考 | 门限 |
| --- | --- | --- |
| A：原RMS | 原模型配套的四通道RMS静息参考 | 原ON/OFF |
| B：当天RMS | 本次明确放松阶段建立的RMS参考 | 由本次校准记录选择 |
| C：当天TKE | 同一放松阶段建立的TKE参考 | 由同一批校准记录选择 |

三组同时处理同一份原始输入，使用相同的滤波、分析窗口、20维特征、固定SVM、启动持续条件、稳定等待、投票规则和释放窗数。界面的单选项只切换显示哪组，不改变其他组的计算。

B与C使用当天参考，可以帮助区分“重新校准参考的收益”与“TKE算法的额外收益”。如果只比较A与C，两种影响会混在一起。

## 3. 运行条件

- Windows桌面环境，推荐沿用训练该模型的`bci`环境。
- OpenBCI，250 Hz；流可有8通道，默认选前4通道，输入单位为μV。
- OpenBCI GUI的Networking：Protocol=`LSL`，Data Type=`TimeSeriesRaw`，Name=`rps_raw`，并启动发送。
- 1.0.1起，匹配LSL流名时忽略名称首尾的Tab和空格；日志仍保留真实名称。如多个流去空白后同名，仍会拒绝不唯一的匹配。
- 分类模型必须是配套二分类流程生成的`daily_model.joblib`，类别0为石头、1为布。
- 需要与该模型匹配的`replay_detector_config.json`；程序会核对模型哈希和预处理契约。
- 使用`--run`时，传入包含`pipeline_state.json`的完整流程输出目录，不是原始TXT路径。

依赖：

```powershell
conda activate bci
python -m pip install numpy scipy scikit-learn joblib pylsl
```

已有joblib模型应使用与训练兼容的数值库版本。先核查原环境，不要为测试随意升级整套环境。

## 5. 一轮操作流程

### 5.1 等待预热

程序连接LSL后，沿用模型配置中的因果滤波预热。等待收到及时、可用的数据，再开始记录。

### 5.2 测静息30秒

保持手和前臂自然放松，点击“测静息”。尽量沿用训练时的姿势，避免移动线缆、触碰电极或调整手臂支撑。

静息阶段有效窗口不足85%，或出现连续性分段变化，会拒绝该次静息校准。没有记录动作前，可以重新测静息。记录过校准动作后若要整轮重做，请重开程序，保留本轮日志。

### 5.3 记录动作校准

1. 点击“记录校准动作”。按钮没有石头/布选项。
2. 自由做石头或布，保持至4秒记录窗口结束；使用与训练接近的自然力度。
3. 窗口结束后，点击“实际是石头”或“实际是布”。
4. 放松约4秒，再开始下一次。
5. 两类有效校准动作各至少3次。

校准阶段收集门控样本，不发出三组正式动作事件。点击“冻结门限”后才启用三组自动输出。

校准标签仅帮助选择门控参数、平衡两类的检出覆盖。门限搜索依据有没有检出、静息误输出、重复输出和响应时间；不会按SVM分类是否正确来挑选门限，也不会重训SVM。

### 5.4 冻结门限

点击“冻结门限”。程序选择B/C的ON/OFF并保存配置；投票等规则沿用原门控，保持三组一致。

门限计算完成后会清理积压输入、重新预热。请继续放松，等收到新数据。正式测试中参考和门限保持冻结；事后标签不改变检测器，也不解除一次动作输出后的锁定。

如果校准中仍有漏检或静息误输出，程序会提示。短时校准不能证明门限已经适合长期或跨日使用，应继续用独立动作测试验证。

### 5.5 正式测试

建议石头、布各10次，顺序打乱，保持与校准相近的力度。

1. 自然放松约4秒。
2. 点击“记录一次测试”，随后自由做一种动作。
3. 保持至4秒窗口结束，然后放松。
4. 记录结束后确认实际动作；没有输出也必须标注。

“记录一次测试”只保存评估起止时间，不启动、不重置检测器，也不预选类别。三组在门限冻结后持续自动检测，达到条件即可输出，不必等满4秒。窗口外的自由动作也可能输出，但缺少明确试次和真值，不计入按试次正确率。

某组一直没有释放，也保留其状态和漏检结果；不通过标签按钮强制放行。4秒截止后才来的输出仍保留日志，本次按记录窗口计漏检，同一个动作不要再补记成另一次成功动作。

数据质量不足的试次会标记无效，保留标签和原因；它们不进入有效测试分母，并单独报告。“本次作废”也会保留审计记录，不删除原始输入。

### 5.6 静息测试60秒

点击“静息测试”，按提示持续放松。只有明确标记的静息测试时段用于计算静息误输出频率。

静息质量覆盖不足85%时，误输出/分钟留空，不把缺数据期间的零输出当作良好表现。

### 5.7 停止并保存

点击“停止并保存”，等待完成提示。打开输出子目录中的`OPEN_REPORT.html`。

## 6. 活动值怎样计算

各通道TKE使用过去和当前三个采样点：

\[
E_c[t]=\left|x_c[t-1]^2-x_c[t-2]x_c[t]\right|
\]

这是相对于中间采样点延迟一个采样点的实时因果实现，在250 Hz下为4 ms。它没有使用尚未收到的未来采样点；TKE历史随数据包连续保存，缺口后重置并重新预热。

在与分类同步的窗口中求平均TKE，得到每个通道的活动能量。各通道除以本次静息窗口能量的中位数，再取四个比值中最高两个的平均，作为C组活动分数。

B组使用同样的归一化和最高两通道平均规则，通道指标换成RMS。A组沿用旧参考。

分析窗口和更新步长读取模型配置，常用为200 ms与100 ms。分类特征继续是每通道MAV、RMS、WL、ZC、SSC，共20维，不将TKE替换进SVM特征。

TKE原始指标的单位为μV²；归一化后的活动分数无量纲。它与原RMS活动分数刻度不同，不能照搬旧ON/OFF数值。界面的活动条不是分类概率或准确率。

## 7. 怎样看结果

| 指标 | 定义与解释 |
| --- | --- |
| 按动作总正确率 | 首次输出正确的有效已标注测试数 / 全部有效已标注测试数；漏检在分母中 |
| 已输出动作准确率 | 正确 /（正确＋错误）；须同时查看漏检，不能单独据此选方案 |
| 漏检 | 4秒记录窗口内没有任何输出 |
| 重复输出 | 同一记录窗口内首次输出以外的额外输出次数 |
| 静息误输出/分钟 | 明确静息测试段内的输出数 / 可用静息时长；质量覆盖不足时留空 |
| 按钮到首次输出时间 | 从“记录一次测试”到首次输出；未输出试次另外统计，不参与该时间的中位数 |
| 窗口结束到释放等待 | 从任务记录窗口结束，到该组首次确认释放；保存在JSON中，不等同于真实肌肉放松延迟 |

石头和布分别报告正确、错误和漏检。优先比较“在静息误输出不明显增加的前提下，布漏检是否下降、响应是否缩短”。20次动作只用于初步筛选；再次换一天重复后，才能评价重复性。

按钮到输出时间包含人的动作反应时间。若要测真实动作起始延迟，应使用同时拍到手和界面的录像或独立传感器核对起点；本程序没有自动生成该真值。

旧模型的跨日分类错误不会仅靠更换门控消失。若“布能及时触发，但经常输出石头”，下一步应检查当天分类模型和特征，而不是继续降低活动门限。

## 10. 常见问题

| 现象 | 先看什么 |
| --- | --- |
| 校准时不出现石头/布正式输出 | 先完成静息、两类各3次动作和冻结门限；校准阶段不发正式事件 |
| 旧RMS组一直要求放松 | 看A的活动值与OFF；同时比较B/C是否能释放，不用标签强制重置 |
| 三组都没有输出 | 看LSL是否收到及时数据、QC、连续性、活动门限、稳定投票各状态 |
| 布超过门限却显示不稳定 | 查看候选类别和投票；降低门限不能直接修复类别分不清 |
| 运行后提示模型与门控不匹配 | 使用同一次流程输出的两个文件，或正确的`pipeline_state.json`目录 |
| 找不到LSL或有多个同名流 | 用`--list-streams`；核查GUI发送状态，必要时用`--source-id`限定 |
| 列出的流名是`"\trps_raw"`而旧版匹配不到 | 前导`\t`是隐藏Tab；更新到1.0.1，或在GUI停止LSL、将Name全选重输为`rps_raw`后重新启动LSL |
| 数据中断/过时 | 先检查GUI和时间戳日志；可点击重连LSL，恢复后重新预热、先放松 |
| GUI RMS与Python RMS不同 | 核对滤波与统计窗口；流名和低LSL年龄不能单独证明物理同步 |

## 12. 方法来源与边界

方法参考：Li等（2021），[Control of Newly-Designed Wearable Robotic Hand Exoskeleton Based on Surface Electromyographic Signals](https://doi.org/10.3389/fnbot.2021.711047)。

本实验借鉴绝对TKE区分活动与放松的思路，并适配现有OpenBCI四通道流程。参考归一化、最高两通道聚合、校准门限搜索及评估窗口是本项目的工程选择，不是对论文全部方法的逐项复现；没有照搬论文的数值门限或在线成绩。
