# 石头 / 布：点击后做动作4秒，再判断

版本：`1.0.0-rp-manual4s`，2026-11-22。

入口是独立完整脚本 **`09_live_rp_button_4ch.py`**，适用于已有石头/布二分类模型。无需导入07或08脚本，也无需重新训练才能试跑。它复用已有扩展版的滤波、20维特征、固定SVM、日志和事后标注模块，将按钮采集设为唯一实时触发方式。

## 这次改变了什么

| 环节 | 按钮版的行为 |
|---|---|
| 启动一次识别 | 点击“开始识别”，按钮不包含类别 |
| 动作开始 | 点击后开始做石头或布，保持约4秒 |
| 静息测量 | 不要求先测8秒或30秒静息 |
| 活动与释放门限 | 不要求超过ON，也不要求降到OFF |
| 类别稳定 | 到固定采集时刻后汇总有效窗口多数票，不等待连续3窗同类 |
| 输出次数 | 每次点击最多输出一次，之后保留结果 |
| 实际动作标签 | 模型输出后，才点击“实际是石头 / 实际是布” |
| 下一次 | 标注上一条结果后，可再次点击开始；程序不以放松门限解除锁定 |
| 无效输入 | 质量不合格、数据过时或连续性中断时提示重做，不强制输出类别 |

这是**由用户按钮指定采集时间的二分类**。点击后如果一直静息，固定的两类SVM仍可能把静息分成石头或布，因为模型没有静息类别。这个版本解决自动门控等待，不代表已经改善跨天分类能力。

`08_live_rp_tke_compare_4ch.py`中的“记录一次测试”只是给自动门控试验划定统计时间；本脚本的“开始识别”会实际启动一次固定时长的分类采集。要测试这次行为，请直接运行09入口。

## 2. 启动OpenBCI GUI

1. 连接板卡，启动数据流，确认前四路肌电输入正常。
2. Networking选择LSL，Data Type选择 **TimeSeriesRaw**，Name填写 `rps_raw`。
3. Type可填写 `EMG`，然后点击启动LSL。下面的命令不限制Type，因此仅将标签填成EEG不会阻止连接；真正需要核对的是数据类型、单位、通道和采样率。

默认读取LSL第1、2、3、4通道，250 Hz，输入单位μV。GUI的显示滤波不代替脚本内与模型一致的滤波。不要把已滤波的TimeSeries输出当作TimeSeriesRaw发送。

此前发现的流名 `"\trps_raw"` 含隐藏Tab，本脚本会去除流名两端空白后匹配。如果去空白后仍有多个同名流，程序会拒绝猜测；关闭重复输出，或通过 `--source-id` 指定来源。

## 3. 完整实时命令

在PowerShell中执行，不要复制提示符 `>>`：

```powershell
conda activate bci
Set-Location "D:\肌电\news\new2\RP_BINARY_4CH"

python .\09_live_rp_button_4ch.py `
    --run "D:\肌电\news\new2\RP_BINARY_NEW_DAY\OLD_DATA_20261108_141306_987" `
    --stream-name rps_raw `
    --manual-duration-seconds 4 `
    --output "D:\肌电\news\new2\RP_BINARY_LIVE_BUTTON_4S"
```

默认就是按钮模式，不需要加 `live` 子命令，也不需要调用旧的 `run_rp_binary.py`。`--manual-duration-seconds` 支持3～4秒，默认4秒。

已有 `bci` 环境中的依赖可继续使用。若提示缺少模块，在同一环境执行：

```powershell
python -m pip install numpy pandas scipy scikit-learn joblib pylsl
```

已有joblib模型需要与训练时兼容的数值库版本；能正常加载旧模型时无需为了这个脚本主动升级环境。

## 4. 界面怎么操作

1. 看到“等待点击开始识别”且底部按钮可点后，点击 **开始识别**。初次连接仍需要完成模型规定的滤波预热，并收到及时、质量合格的数据。
2. **点击后开始动作**，做石头或布并保持到4秒倒计时结束。前1秒用于起手过渡；不需要提前告诉程序做哪一类。
3. 倒计时结束，模型给出一个类别。传输与处理会增加少量时间；收到完整及时数据时才会输出。界面进度条显示采集时间，不显示置信度或活动门限。
4. 松手，按刚才真正做的动作点击 **实际是石头** 或 **实际是布**，保存正确/错误记录。标签仅用于统计，不重训SVM，不修改此次预测，不作为下次推理输入。
5. 标注完再点“开始识别”，进行下一次。手臂自然放松便于重复动作，但不需要达到旧OFF门限。

界面保留分类窗口四路RMS、接收率、LSL数据年龄、已标注统计，以及“重新同步LSL”和“停止接收并保存”。重新同步只重新订阅、清理Python入口缓存并重新预热，不要求重新连接板卡，也不能清空GUI或板卡上游队列。

若提示“有效信号不足”“数据连续性中断”或“未收到完整数据”，检查输入后重新点击。不要把失效采集解释为模型已经预测错误。需要统计有效动作却无输出时，可使用“本次没有输出：记录一次漏检”，同一次动作只记录一次。

## 5. 4秒里怎样判断

使用现有模型配置的因果滤波与特征提取，不改变标准化器或SVM。本项目已有模型通常为200 ms分析窗、100 ms步长。

- 从点击时刻建立一个固定4秒区间，排除点击前缓存的数据。
- 前1秒用于动作过渡，后3秒取完整分析窗。250 Hz、50点窗、25点步长时最多约29窗，采样与按钮边界不对齐会稍少。
- 至少需要24个质量合格的窗口；从这些窗口的石头/布候选取多数票。票数相同时，用平均SVM决策分数打破平票；该分数不是识别概率。
- 不使用活动ON/OFF，也不因候选类别有波动而继续等十几秒。到时间后，有足够有效数据就判断，否则明确失败并允许重做。
- 默认允许最多约0.75秒数据到达余量。这个余量不会延长到十几秒，也不会将4秒之后的动作窗口加入投票。若接收线程本身报错或阻塞，需先恢复接收。

SVM窗口在采集期间逐窗计算，**最终类别在采集结束后确定并显示**。按钮只给出时间，没有给出真实类别；真实标签在输出后另存。

```powershell

```

每次运行会在输出父目录下新建 `RP_BINARY_MANUAL4S_...` 子目录，包含：

- `live_configuration.json`：配套模型、实际流信息、采集参数以及 `activity_gate_enabled=false`、`button_specifies_class=false`。
- `manual_requests.json`：每次按钮请求、完成时间、成功/超时/中断状态。
- `raw_samples.csv`、`window_trace.csv`、`events.csv`：输入、逐窗候选和最终事件。
- 事后标注文件与 `session_summary.json`：实际动作、正确率和传输/质量诊断。

查看准确率时，未标注输出不进入分母；手动漏检会进入分母。该统计针对按钮采集的动作分类，不代表自动动作起始检测、静息误触发率或肌肉起始到输出的完整延迟。

## 7. 已完成验证与限制

本地通过14项合成自检，覆盖：4秒结束边界、点击前和过渡期排除、很低活动也能判断、无需放松即可再次开始、混合候选多数票、超时与质量失败、连续性中断、过时数据抑制、流名隐藏Tab匹配和事后标签隔离。

另外用模拟LSL跑通两次按钮采集与事后标注：一次低幅信号、一次高幅信号，都在约4.124秒完成，模型和原配置文件未被修改。这是软件逻辑验证，**未在你的Windows界面及真实板卡上实测**，不能将模拟耗时或正确结果当作真实准确率。

你当前复用的是2026-11-04校准模型。可先用它验证按钮流程；若4秒内能正常输出但类别仍不准，应另查当天电极位置、信号分布与分类模型，或用当天数据校准。不要只根据按钮流程改善就认定跨天模型已改善。
