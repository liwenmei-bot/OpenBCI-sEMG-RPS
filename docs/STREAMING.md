# 实时数据流与排查

数据路径为板卡采样、OpenBCI GUI、LSL `TimeSeriesRaw`、Python连续滤波、窗口特征、冻结SVM、活动门控/投票、结果与事后标注。

GUI Networking中的流名只是名称，`rps_raw`本身不能证明数据类型正确；应检查Data Type=`TimeSeriesRaw`，输入通道与单位和模型一致。GUI显示滤波设置可能与Python模型的20—100 Hz、50 Hz陷波不同。GUI显示的RMS和Python窗口RMS还可能使用不同统计时段，截图读数不同不能单独证明接线错或延迟。

默认程序按250 Hz、前4通道、μV分析。不要把GUI已滤波的输出冒充原始输入重复处理，也不要只为让两边数字接近而改模型预处理。若要比较显示，先明确两端数据类型、滤波、窗口、时间位置与通道映射。

| 日志/指标 | 能说明什么 | 不能单独证明什么 |
|---|---|---|
| `raw_samples.csv`与`window_trace.csv` | 保存的输入能否按相同因果滤波复现RMS和活动值 | GUI显示或物理动作与输入严格同步 |
| LSL数据/分析窗口年龄 | Python看到的时间戳与处理时刻差异；过时窗口是否被抑制 | 板卡到GUI的完整上游等待、肌肉起始延迟 |
| 接收速率与缓存点数 | 当前Python接收行为、是否积压 | 没有计数器时的全部丢包与板卡真实性 |
| `detector_state` | 等放松、门限以下、稳定等待、投票、已锁定等 | 未标注手势的真实正确率 |
| `action_labels.csv` | 人工确认过的输出及手动漏检 | 未记录动作/静息的完整真值 |

若必须重连板卡才恢复，先保留异常那次的日志，再对照重同步LSL前后窗口年龄、窗口RMS、接收速率和状态。程序的重新同步只重建Python订阅与本地状态，不能承诺清理GUI/板卡队列。单纯调整活动阈值也不能修复上游积压。

停止保存后运行：

```powershell
python run.py diagnose --logs "本次实时输出目录"
```

诊断器独立从原始CSV复算，输出HTML、JSON和逐窗口检查表。若只有GUI截图、没有原始输入与真实动作时间标记，无法可靠区分滤波差异、基线漂移与物理延迟；报告会保留这一限制。

预测与日志快照可能被Excel/WPS短暂占用。实时引擎保留重试与恢复保存逻辑；分析前先停止实时程序，并核对目录内最终文件或recovery文件。该处理不等于磁盘错误都可忽略。
